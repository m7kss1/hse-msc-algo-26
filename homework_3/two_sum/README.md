# Задача 1. Two sum

## Идея

Перебор всех пар работает за O(n^2). Можно отсортировать и идти двумя указателями с концов, это O(n log n), но тогда приходится помнить исходные индексы. Самый быстрый вариант - хеш-таблица, один проход

Для каждого `arr[j]` пара однозначно задана: нужен элемент `k - arr[j]`. Идем по массиву слева направо и держим словарь: значение -> индекс, на котором оно встретилось. На шаге `j`:

1. ищем в словаре число `k - arr[j]`. Нашли на индексе `i` - это ответ `i j`, причем `i < j` автоматически, потому что `i` мы видели раньше
2. не нашли - кладем `arr[j]` в словарь и идем дальше

Важен порядок: **сначала ищем, потом кладем**. Если класть сначала, при `arr[j] = k / 2` элемент найдет сам себя

Каждая пара `(i, j)` будет замечена на шаге `j`: к этому моменту `arr[i]` уже лежит в словаре. Поэтому пару не пропустим

Решение не опирается на гарантии условия:

* числа любого знака, нули, повторы - без разницы
* если пары нет, возвращаем `None`, программа печатает `пары нет`
* если пар несколько, отдаем пару с наименьшим `j`, а при равенстве с наименьшим `i`

## Сложность

* **Время O(n)** в среднем: один проход, на каждом шаге поиск и вставка в хеш-таблицу за O(1) в среднем. Худший случай - O(n^2), если специально подобрать числа с одинаковыми хешами, чтобы каждая операция с таблицей стоила O(n)
* **Память O(n)**: в словаре в худшем случае окажутся все элементы, кроме последнего

## Как это работает по шагам

```
arr = [3, 8, -1, 5, 3, 12], k = 6

 шаг |   j | arr[j] | ищем k - arr[j] | нашли        | seen (значение: индекс)
------------------------------------------------------------------------------
   1 |   0 |      3 |               3 | -            | {3: 0}
   2 |   1 |      8 |              -2 | -            | {3: 0, 8: 1}
   3 |   2 |     -1 |               7 | -            | {3: 0, 8: 1, -1: 2}
   4 |   3 |      5 |               1 | -            | {3: 0, 8: 1, -1: 2, 5: 3}
   5 |   4 |      3 |               3 | да, i = 0    | {3: 0, 8: 1, -1: 2, 5: 3}

ответ: 0 4
```
