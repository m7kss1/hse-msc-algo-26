# Задача 1. Makeheap

## Идея

Minheap хранится в массиве: у узла `i` дети `2i + 1` и `2i + 2`, родитель `(i - 1) // 2`. Свойство кучи: каждый родитель не больше своих детей, поэтому минимум стоит в `arr[0]`. Обе функции перестраивают массив на месте и возвращают `None`, как `list.sort`. Библиотеки не используются, `sift_up` и `sift_down` написаны вручную

**makeheap_n_log_n** добавляет элементы в кучу по одному. Префикс `arr[:i]` уже куча, к нему добавляем `arr[i]` и поднимаем (`sift_up`): пока элемент меньше родителя, меняем их местами. Подъем меняет только путь от `i` к корню, на этом пути после обмена родитель становится меньше обоих детей. После последнего элемента кучей становится весь массив

**makeheap** строит кучу снизу вверх. Узлы с индексами от `n // 2` листья, каждый лист сам по себе куча. Идем по остальным узлам от `n // 2 - 1` к корню и опускаем каждый (`sift_down`): пока элемент больше меньшего из детей, меняем его с этим ребенком. Когда опускаем узел `i`, поддеревья его детей уже кучи, поэтому после опускания кучей становится и поддерево `i`. Последним обрабатываем корень, и кучей становится весь массив

Оба способа дают корректную кучу, но сами кучи могут отличаться, потому что элементы переставляются в разном порядке

## Сложность

`n` это длина массива, высота кучи `h = floor(log2 n)`. Полное доказательство с выписанной суммой в [proof.md](proof.md)

* **makeheap_n_log_n: время O(n log n)**: элемент с индекса `i` поднимается не больше чем на свою глубину `floor(log2(i + 1)) <= log2 n`. На убывающем массиве каждый новый элемент поднимается до корня, и больше половины элементов лежит на глубине не меньше `log2 n - 2`, поэтому в худшем случае Θ(n log n)
* **makeheap: время O(n)**: узел опускается не больше чем на свою высоту. На уровне `d` не больше `2^d` узлов, каждый опускается не больше чем на `h - d` уровней:

  ```
  sum_{d=0..h} 2^d (h - d) = 2^h * sum_{j=0..h} j / 2^j < 2^h * 2 <= 2n
  ```

  Подъем стоит глубину узла, опускание стоит высоту. Почти все узлы внизу дерева: у них глубина около `log2 n`, а высота 0 или 1. Поэтому сумма высот линейна
* **Память O(1)** для обеих функций: перестановки на месте, `sift_up` и `sift_down` итеративные

## Как это работает по шагам

Убывающий массив `[7,6,5,4,3,2,1]` это худший случай для подъема (`make demo`):

```
makeheap_n_log_n: добавляем arr[i] и поднимаем
   i | элемент | массив после шага     | обменов
   1 |       6 | [6, 7, 5, 4, 3, 2, 1] | 1
   2 |       5 | [5, 7, 6, 4, 3, 2, 1] | 1
   3 |       4 | [4, 5, 6, 7, 3, 2, 1] | 2
   4 |       3 | [3, 4, 6, 7, 5, 2, 1] | 2
   5 |       2 | [2, 4, 3, 7, 5, 6, 1] | 2
   6 |       1 | [1, 4, 2, 7, 5, 6, 3] | 2
  всего обменов 10

makeheap: опускаем внутренние узлы с конца
   i | элемент | массив после шага     | обменов
   2 |       5 | [7, 6, 1, 4, 3, 2, 5] | 1
   1 |       6 | [7, 3, 1, 4, 6, 2, 5] | 1
   0 |       7 | [1, 3, 2, 4, 6, 7, 5] | 2
  всего обменов 4
```

В первом способе каждый новый элемент меньше всех предыдущих и поднимается до корня: четыре листа проходят по два уровня. Во втором листья не двигаются вообще, опускаются только три внутренних узла. Итоговые кучи:

```
makeheap_n_log_n          makeheap
       1                      1
     /   \                  /   \
    4     2                3     2
   / \   / \              / \   / \
  7   5 6   3            4   6 7   5
```

## Сравнение времени

`make bench` строит кучу обоими способами на случайном массиве (seed 42), на убывающем и на возрастающем массиве. Время это лучшее из трех запусков, обмены считаются отдельно через список-счетчик `SwapCounter`, поэтому от машины не зависят. Пример одного запуска:

```
массив                 n |       время, с        |        обмены
                         |    N log N          N |    N log N          N
случайный          10000 |     0.0024     0.0021 |      12778       7495
по убыванию        10000 |     0.0103     0.0023 |     113631       9992
по возрастанию     10000 |     0.0011     0.0009 |          0          0
случайный         100000 |     0.0247     0.0210 |     127717      74339
по убыванию       100000 |     0.1356     0.0239 |    1468946      99990
по возрастанию    100000 |     0.0110     0.0087 |          0          0
случайный        1000000 |     0.2525     0.2377 |    1283241     744819
по убыванию      1000000 |     1.6638     0.2621 |   17951445     999988
по возрастанию   1000000 |     0.1118     0.0904 |          0          0
```

* У `makeheap` время растет линейно: при росте `n` в 10 раз время растет примерно в 10 раз, обменов всегда меньше `n`
* На убывающем массиве `makeheap_n_log_n` медленнее в 4.5 раза при `n = 10^4` и в 6.3 раза при `n = 10^6`: отношение растет вместе с `log n`. Обменов около `n (log2 n - 2)`, то есть Θ(n log n)
* На случайном массиве разница небольшая: новый элемент в среднем поднимается примерно на 1.3 уровня, а не до корня. Оценка O(n log n) это худший случай, а `makeheap` дает O(n) на любом входе
* Возрастающий массив уже куча: обменов нет, обе функции делают один проход сравнений

Время зависит от машины и запуска, это демонстрация, а не тест. Размеры можно задать: `make bench ARGS="1000 10000"`

## Запуск и тестирование

```bash
make test                           # корректность кучи, границы, случайные массивы, число обменов
make run ARGS="5 3 8 1 9 2 7"      # обе кучи на своем вводе
echo "5 3 8 1 9 2 7" | make run    # ввод через stdin
make examples                       # примеры
make demo                           # пошаговая визуализация
make bench                          # сравнение времени и числа обменов
make help                           # список команд
```
