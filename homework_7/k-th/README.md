# Задача 2. K-th minheap

## Идея

Нужен `k`-й по величине элемент с учетом повторов. Сортировать весь массив не нужно: достаточно хранить `k` наибольших из уже просмотренных элементов. Наименьший из них и есть `k`-й по величине, а наименьший удобно доставать из minheap размера `k`

1. Кладем первые `k` элементов в кучу и строим ее снизу вверх за O(k)
2. Идем по остальным элементам. Если элемент больше вершины кучи, вершина больше не входит в `k` наибольших: заменяем ее новым элементом и опускаем его на свое место. Иначе пропускаем элемент
3. После прохода вершина кучи это ответ

**Почему это верно.** Инвариант: после просмотра первых `i` элементов в куче лежат `k` наибольших из них (повторы считаются отдельными элементами). Сначала в куче ровно первые `k` элементов. Пусть пришел `x`:

* `x > heap[0]`: теперь есть `k` элементов больше `heap[0]` (`x` и остальные `k - 1` в куче), значит `heap[0]` выпадает из `k` наибольших, а `x` в них входит
* `x <= heap[0]`: хотя бы `k` элементов не меньше `x`, поэтому набор `k` наибольших по значениям не меняется. При `x = heap[0]` замена дала бы ту же кучу, ее можно пропустить

В конце в куче `k` наибольших элементов всего массива, их минимум `heap[0]` это `k`-й по величине

**Две реализации** с одинаковым алгоритмом:

* `kth_largest` использует свою кучу: `sift_down`, `heapify` (снизу вверх, как `makeheap` из задачи 1) и `heapreplace` (записать новое значение в вершину и опустить). Это та часть интерфейса `heapq`, которая нужна алгоритму
* `kth_largest_heapq` использует `heapq.heapify` и `heapq.heapreplace`

Входной массив не меняется, в кучу копируются первые `k` элементов. Хвост обходим по индексу, без среза `nums[k:]`, чтобы не копировать еще `n - k` элементов. При пустом массиве или `k` вне диапазона от 1 до `n` обе функции вызывают `ValueError`

## Сложность

`n` это длина массива

* **Время O(n log k)**: построение кучи O(k), затем не больше `n - k` замен вершины, каждая опускает элемент на глубину кучи `floor(log2 k)`. Итого O(k + (n - k) log k). Пропуск элемента стоит O(1), поэтому на возрастающем массиве замены происходят на каждом шаге, а на убывающем ни одной
* **Память O(k)** на кучу. При `k = 1` это поиск максимума за O(n) и O(1), при `k = n` поиск минимума: построение кучи O(n) и ни одной замены

Сортировка дала бы O(n log n), куча выгоднее при `k`, много меньших `n`. Обе реализации имеют одну асимптотику, но `heapq` написан на C и работает быстрее в константу раз

## Как это работает по шагам

Второй пример из условия (`make demo`), четвертый по величине:

```
nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4
куча из первых 4: [3, 2, 3, 1] -> [1, 2, 3, 3], вершина 1

  i | элемент | действие                 | куча         | вершина
  4 |       2 | 2 > 1, меняем вершину    | [2, 2, 3, 3] | 2
  5 |       4 | 4 > 2, меняем вершину    | [2, 3, 3, 4] | 2
  6 |       5 | 5 > 2, меняем вершину    | [3, 4, 3, 5] | 3
  7 |       5 | 5 > 3, меняем вершину    | [3, 4, 5, 5] | 3
  8 |       6 | 6 > 3, меняем вершину    | [4, 5, 5, 6] | 4

ответ: 4
```

Разберем шаг `i = 6`. Куча `[2, 3, 3, 4]`, пришла пятерка. Записываем ее в вершину и опускаем, каждый раз меняя с меньшим ребенком:

```
    5              3              3
   / \            / \            / \
  3   3    ->    5   3    ->    4   3
 /              /              /
4              4              5

[5, 3, 3, 4]   [3, 5, 3, 4]   [3, 4, 3, 5]
```

Повторяющиеся значения считаются отдельными элементами: в куче одновременно лежат две двойки, потом две тройки, в конце обе пятерки. Поэтому ответ 4: по убыванию идут 6, 5, 5, 4, а без учета повторов четвертым было бы 3. В первом примере есть и пропуски:

```
nums = [3, 2, 1, 5, 6, 4], k = 2
куча из первых 2: [3, 2] -> [2, 3], вершина 2

  i | элемент | действие                 | куча   | вершина
  2 |       1 | 1 <= 2, пропускаем       | [2, 3] | 2
  3 |       5 | 5 > 2, меняем вершину    | [3, 5] | 3
  4 |       6 | 6 > 3, меняем вершину    | [5, 6] | 5
  5 |       4 | 4 <= 5, пропускаем       | [5, 6] | 5

ответ: 5
```

## Запуск и тестирование

```bash
make test                                  # примеры, границы, повторы, случайные и большие массивы
make run ARGS="3 2 1 5 6 4 / 2"           # массив и k через /, печатает ответ обоих способов
printf "3 2 1 5 6 4\n2\n" | make run      # ввод двумя строками
make examples                              # примеры из условия
make demo                                  # пошаговая визуализация
make help                                  # список команд
```

Тесты сравнивают обе реализации с ответом через сортировку, проверяют все `k` от 1 до `n` на граничных массивах, что входной массив не меняется, что своя куча не обращается к `heapq` и что после `heapify` и каждого `heapreplace` сохраняется свойство кучи
