# Задача 1. Tracer

## Идея

Декоратор оборачивает функцию: перед вызовом печатает ее имя и аргументы, после вызова печатает имя и возвращенное значение. Отступ в два пробела на каждый уровень показывает, какой вызов ждет завершения другого

Глубину храним в `ContextVar`: вложенные декорированные функции видят общий счетчик, но у разных контекстов исполнения он свой. При входе увеличиваем глубину, а в `finally` возвращаем прежнее значение по токену. Это важно при исключении: иначе после ошибки следующий вызов остался бы с лишним отступом. Исключение печатается и пробрасывается дальше, декоратор его не подавляет

## Сложность

`d` это глубина вызова, `a` и `r` это длины текстовых представлений аргументов и результата

* **Время O(d + a + r)** на один вызов для формирования и вывода строк, не считая работы самой функции и стоимости построения `repr`
* **Память O(d + a + r)** на строки одного вызова. Глубина и память стека самой рекурсии зависят от исходной функции

## Как это работает по шагам

Для `factorial(4)` (`make demo`):

```
-> factorial(4)
  -> factorial(3)
    -> factorial(2)
      -> factorial(1)
      <- factorial = 1
    <- factorial = 2
  <- factorial = 6
<- factorial = 24
```

`factorial(4)` не может вернуть результат, пока не завершится `factorial(3)`, тот ждет `factorial(2)` и так далее. На обратном пути отступ уменьшается, и результат каждого вызова виден на том же уровне, что и его вход

## Запуск и тестирование

```bash
make test       # прогнать тесты, в том числе восстановление глубины после ошибки
make demo       # стек вызовов факториала
make examples   # пример
make help       # список команд
```
